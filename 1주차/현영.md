# 내용정리
## 1. 영화 예매 도메인
### 용어정리
- 도메인이란?
  - 사용자가 프로그램을 사용하는 주제 영역
  - 소프트웨어로 구현할 요구사항의 범위. 모든 요구사항들을 소프트웨어로 옮길 수는 없다.
- 다중성이란?
  - 도메인 개념들끼리 연결된 숫자.
  - ex) 영화와 할인 정책은 1:0 or 1:1. 하나의 영화 당 최대 한 개의 할인 정책
  - ex) 할인 정책과 할인 조건은 1:N. 하나의 할인 정책 당 최소 한 개의 할인 조건

### ex) 영화 예매 도메인
  - 영화
  - 상영
  - 할인 정책
    - 금액 할인 정책
    - 비율 할인 정책
  - 할인 조건
    - 순서 조건 (조조영화, N회 상영)
    - 기간 조건 (특정 날짜, 시간 상영)
  - 예매

## 2. 절차적인 설계 개선하기
### 2-1. 절차적인 설계
- **절차적인 설계란?**
  - 프로그램 = 데이터 + 프로세스
  - **이때 데이터와 프로세스를 개별적인 모듈로 분리하여 구현하는 것을 말함**
  - 도메인 로직을 실행 순서대로 클래스 안에 배치
  - **객체가 누구이고, 어떤 일을 하는지를 객체 자신이 아닌 소비처에서 결정**
  - **중앙집중식 제어 스타일**
  	- 응집도, 결합도 측면에서 문제 발생
- 데이터 접근 객체(DAO, Data Access Object)
	- 영속성 저장소와의 상호작용을 담당하는 객체

### 2-2. 변경과 의존성
- 절차적인 설계가 변경에 취약한 이유
	- 데이터 수정 시 프로세스까지 수정해야 한다.
- **의존성**
	- 다른 코드가 수정될 때 함께 수정될 수 있는 **가능성**
 	- 변경 방향은 의존성의 방향과 반대이다.
- 캡슐화 위반
	- **내부의 데이터를 그대로 노출**
	- 이는 곧, **추측에 의한 설계 전략**
 	- 객체가 사용될 문맥을 고려하지 않고 데이터 설계
  - 객체를 수정해도 어디까지 전파될지 알 수 없음.. 판단을 외부에서 하기 때문

### 2-3. 데이터와 프로세스 통합하기
- **책임의 이동**: 데이터의 게터를 사용해서 판단, 결정하는 로직을 데이터 쪽으로 옮겨라
- **데이터 vs 객체**
	- 데이터: 수동적 (데이터는 외부에 제공만, 외부에서 판단하고 결정)
 	- 객체: **자율적** (능동적으로 자기 자신의 상태를 관리, 스스로 판단하고 결정)
 
### 2-4. 절차에서 객체로
- 연관 관계를 추가하기
- 책임 주도 설계란?
	- 객체를 똑똑하게 만들기 위해서는 객체가 사용될 문맥이 필요. 이를 고려하는 것.
 	- 처음부터 의존성을 고려해서 설계 가능
