# 절차적인 설계

### 절차적인 구현 방식 이란?

- 절차적인 방식은 프로그램을 구성하는 데이터와 프로세스를 개별적인 모듈로 분류해서 구현하는 방식
- **프로그램 :** 데이터와 이 데이터를 사용하는 알고리즘 또는 프로세스의 조합
- 데이터를 먼저 정의하고 데이터를 사용하는 프로세스를 나중에 설계한다

### 클래스

- 객체지향 언어에서는 데이터를 객체안에 보관하기 때문에 클래스를 이용해 데이터를 저장할 코드를 구현
- 일반적으로 테이블당 하나씩 추가하고 테이블의 컬럼별로 하나의 필드를 대응시키는 방식으로 구현

### 알고리즘 설계

- 로직을 실행 순서대로 클래스 안에 배치

### 데이터 접근 객체 (Data Access Object)

- 영속성 저장소와의 상호작용을 담당하는 객체
- 데이터 베이스에 접근해서 영속성 로직을 처리하는 객체
- 일반적으로 테이블당 하나씩 추가한다.

### 절차적인 설계의 핵심

- 데이터가 사용될 문맥을 고려하지 않은 채 독립적으로 데이터 설계
- 데이터가 완성되면 외부의 프로세스에 데이터를 처리하기 위한 로직 구현
- 프로세스를 구현한 클래스의 제어가 집중된다는 특징 (중앙 집중식 제어 스타일)
  - 응집도와 결합도 측면에서 코드를 수정할 때 많은 문제가 발생한다.
    - **응집도 :** 하나의 클래스 안에 얼마나 관련 있는 기능들이 뭉쳐 있는가
    - **결합도 :** 서로 다른 클래스가 얼마나 의존하고 있는가.

```java
DiscountCondition condition = findDiscountCondition(screening, conditions);
if(condition이 존재하면..) {~}

// DiscountCondition이 전달받은 screen, conditions에 따라 단순한 데이터만 return함
// 전달받은 condition에 따라 ReservationService가 요금을 계산함
// DiscountCondttion이 스스로 할인 여부를 판단하지 못하고, 외부에서 계산하는 게 문제

private DiscountCondition findDiscountCondition(Screening screening, List<DiscountCondition> conditions) {
    if(condition.isPeriodCondition()) {
        if(screening.isPlayedIn(condition.getDayOfWeek(), condition.getStartTime(), condition.getEndTime())) {
            return condition;
        }
    } else {
        if(condition.getSequence().equals(screening.getSequence())) {
            return condition;
        }
    }
    return null;
}
```
